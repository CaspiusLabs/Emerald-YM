# Emerald YM 0.1.4 — accepted screen and LEDs baseline

Installed identity FM-1_68000104. User confirmed no flicker, working LEDs and four visible knob values/bars. This is the immutable accepted baseline, not the current controls manual.

## Changes

- Replace periodic whole-LCD clearing with completed tiles in the existing canvas. Unchanged areas are not resent; full clear only on initial draw/explicit invalidation such as updater exit.
- Four cards: tempo 80–180 BPM, density, mutation, transpose−12..+12, large values/bars including bipolar transpose.
- PLAYING/PAUSED, bar,16-step strip, CPU MAX and XRUN counters.
- Original code-drawn Emerald gem, cyan typography/navy cards/16-BIT badge; no extra image/framebuffer.
- PLAY green/dim paused/red overload; REC dim with reseed flash; SEQ bright at mutation 0/dim active; OCT pair indicates update hold. No simulated features on unused buttons.
- Panel sampled every 20 ms; controls posted only on change; complete LED rows avoid transient blanking.

## Evidence

Desktop real renderer/fonts/canvas against memory LCD: no idle writes, exactly one parameter tile, small step-strip update, no ordinary full clear, output bounds and paused/playing/transpose/overload previews. Physical trace:62 samples over 60.6s,48 playing while panel/PLAY/REC were tested. CPU MAX 80%, longest block 4653 us, XRUN 0, overload 0, failed boots 0. Raw passed=false remains because REC reset bar to 1 and failed the original end-bar criterion. Classified as interactive, not a continuous-minute pass or observed audio fault. Earlier 0.1.3 with the same algorithm passed over a minute continuously. User confirmed UI/LED/knob behavior; not all combinations/long sessions tested.

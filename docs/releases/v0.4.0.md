# Emerald YM 0.4.0 — persistent instruments and startup screen

New behavior: all twelve levels and 36 DECAY/COLOR/ECHO values load before audio starts and remain after power-off once saved. The 56-byte EMS1/schema1 payload uses the existing OBJ_PROJ A/B pair at FC000/FD000, with range validation, CRC and header-last commit/readback from storage.c. No new flash area or code/RAM guard is introduced. Another firmware's project data there may be replaced; panel calibration and OTA staging are separate.

An edit marks SAVE * and lights SAVE. Auto-save requires three seconds since the last edit and three seconds with backing paused and no held panel/USB keys. SAVE pauses backing and requests the same quiet save. SAVING is followed by SAVED or SAVE ERR. Failures keep dirty RAM values and do not retry/erase repeatedly; SAVE or a new edit permits a retry. Power-off before SAVED may lose recent edits. This is settings storage, not complete projects: tempo/seed/transpose/PSG enable/selection/FX cursor are not stored.

The header shows EN_VERSION from VERSION below 16-BIT. A short original console-inspired silhouette (circular cartridge deck, vents, red LED) uses the existing tile canvas at boot. USB/panel servicing continues during its display; user activity dismisses it. No copied Sega logo/boot audio or new bitmap buffer.

Audio DSP is identical to 0.3.1. Hot audio 21604 B; RAMTEXT 24492/24576 B; data+BSS 30416/98304 B; pool 101888/344064 B; application 105208 B. The 85% guard and flash-off call/no-soft-double checks remain.

Desktop persistence tests use real storage.c with simulated NOR: complete reboot restore of every source/FX, quiet/edit debounce, cancellation when returning to saved values, interrupted payload/header writes, CRC fallback, rejected foreign/schema/range/oversized records, explicit error retry and timer wrap. Writes stay in FC000/FD000. UI/LED/renderer/update tests are reported separately from physical measurement. The hardware tool refuses effect stress on persistent versions because no remote settings snapshot/restore exists; note-only stress is unchanged.

Physical power-cycle retention was subsequently confirmed by the user on 2026-10-27 for the requested representative level/effect test. All settings, long sessions and cross-firmware update/recovery still require separate evidence. Existing 0.3.x results must not be relabeled as fresh 0.4.0 tests.

Physical audio test: 30 s continuous backing with two/three live notes, neutral FX, passed=true; CPU MAX 65%, max block 3827 us, XRUN 0, overload 0, failed boots 0. User subsequently confirmed power-cycle retention, version label and boot screen; see releases/v0.4.0/user-confirmation.json. This feedback is separate from the desktop simulation and physical audio trace.

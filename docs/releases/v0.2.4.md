# Emerald YM 0.2.4 — wybór instrumentu i jego poziomu

SELECT wybiera źródło, ALGORITHM reguluje tylko wybrane źródło. Poziom każdego
z dwunastu źródeł jest niezależny, 0–100% w krokach 5%. Domyślnie wszystkie
mają 100% zaakceptowanego balansu (PSG zachowuje bazowe wzmocnienie 0.2.2).

| Pozycja SELECT | Źródło |
|---|---|
| 1 | FM BASS |
| 2 | FM LEAD |
| 3–5 | FM CHORD 1, 2, 3 — oddzielne głosy akordów |
| 6 | KICK |
| 7 | SNARE |
| 8 | CLOSED HAT |
| 9 | OPEN HAT |
| 10 | PSG ARP |
| 11 | PSG LIVE — instrument klawiatury, do trzech głosów |
| 12 | PSG NOISE |

Zmiana wyboru SELECT nie zmienia brzmienia. Po przejściu do innego źródła
poprzedni poziom pozostaje ustawiony. REC, pauza i ARP nie zerują poziomów.
Restart przywraca wartości domyślne; nie zapisujemy automatycznie Flash.
PRESETS nadal reguluje dodatkową głośność całej perkusji (DAC i szum PSG),
a MASTER całość. PRESETS 0% wycisza perkusję także wtedy, gdy poszczególne
bębny mają 100%. ARP pozostaje włącznikiem całego PSG.

Na dole ekranu: nazwa wybranego źródła, ALG i jego poziom oraz pasek.
Obok pozostaje PRE DRUM jako poziom magistrali perkusji. CPU/XRUN pozostają
wyłącznie w diagnostyce USB; próg 85% i informacja OVERLOAD bez zmian.

## Implementacja i sprawdzenie

Każdy z pięciu kanałów FM ma własną skalę po DAC discontinuity danego kanału,
przed dodaniem perkusji. Poziomy bębnów są cache'owane przy wyzwoleniu i na
granicy bloku, więc zmiana suwaka obejmuje również trwający ogon próbki.
PSG ARP, LIVE i NOISE mają oddzielne mnożniki. Nie dodano kanałów ani operatorów,
alokacji podczas grania, libm ani double. Poziom 100% pomija skalowanie FM.

Tablica dzielników PSG jest w `.ym_pitch` w XIP: jest odczytywana tylko przy
ustawianiu okresu tonu, nie w pętli generowania próbek oscylatora. Aktywne
okresy i krytyczny renderer pozostają w RAM. Sprawdza to linker/skrypt
budowania, bez zmiany granic pamięci lub kopiowania startup. Audio nie jest
wykonywane podczas operacji Flash-off; stary zakaz wywołań z `.ram_text` do XIP
pozostaje. `.ym_control` nadal zawiera leaf-kontrolery pętli głównej.

Testy komputerowe potwierdzają:

- Każde z 12 źródeł jest słyszalne, gdy pozostałe jedenaście ma 0%.
- Wyciszenie PSG LIVE wycisza trzymaną nutę; ponowne podniesienie poziomu ją
  przywraca bez ponownego naciśnięcia klawisza.
- Domyślny balans ma identyczny hash 7ce44fbe jak 0.2.2; niezależność wielkości
  bloku 256/63, reseed, pauza, allocator i brak alokacji zachowane.
- SELECT i ALGORITHM aktualizują tylko kafelek wybranego źródła 148×34,
  PRESETS tylko kafelek 72×34. Liczniki USB nie powodują zapisów na ekran.
- Testy LED, PSG, no-soft-double, linkera i symulacje OTA/loadera przeszły.
  Odziedziczone porównanie JS pozostaje pominięte, niezaliczone.

Pakiet, pomiary urządzenia i podgląd renderera są zachowywane oddzielnie
w releases/v0.2.4. Podgląd jest obrazem z testu desktopowego, nie zdjęciem FM-1.
Nie traktujemy próby domyślnych poziomów jako pomiaru wszystkich możliwych
kombinacji dwunastu regulatorów ani wielogodzinnej stabilności.

## Wynik końcowego pakietu na FM-1

Zweryfikowany identyfikator: FM-1_68000204. Test 30 s z ciągłym podkładem
i naprzemiennie dwiema/trzema nutami live E4/B4/E5: passed=true,
CPU MAX 85%, maksymalny blok 4985 us, XRUNS 0, overload 0, failed boots 0.
Wartość CPU jest raportowana jako całkowity procent przez istniejący protokół.
Zapas jest bardzo mały; nie podnoszono ani nie usuwano ochrony.

Wstępna próba przed pominięciem mnożenia przy unity również osiągała 85%
(4980 us). Nie przypisujemy optymalizacji potwierdzonej poprawy czasu na
podstawie różnicy kilku mikrosekund. Oba surowe raporty zachowano i opisano
osobno; tylko końcowy odpowiada zachowanemu pakietowi wydania.
